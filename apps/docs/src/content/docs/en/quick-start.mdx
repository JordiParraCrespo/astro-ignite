## Prerequisites

- Node 22.12 LTS or later (required by Astro 7 and, in the starter template, `@astrojs/node@^11`)
- A package manager — pnpm (recommended), npm, yarn, or bun

<Steps>
  <Step title="Scaffold a new site">
    Run the create command with your package manager of choice:

    <CodeGroup>
      <CodeBlock filename="npm" prompt>{`npm create astro-ignite@latest my-site`}</CodeBlock>
      <CodeBlock filename="pnpm" prompt>{`pnpm create astro-ignite my-site`}</CodeBlock>
      <CodeBlock filename="yarn" prompt>{`yarn create astro-ignite my-site`}</CodeBlock>
      <CodeBlock filename="bun" prompt>{`bun create astro-ignite my-site`}</CodeBlock>
    </CodeGroup>

    You'll be asked eight questions — template kind, project directory, site name, site URL, default locale, additional locales, email provider, and package manager — then shown a summary and a final **Proceed?** confirm. Pick or accept defaults; the whole flow takes around fifteen seconds.

    <Callout variant="tip" title="Two equivalent commands">
      `npm create astro-ignite@latest` is a shim that runs `npx astro-ignite bootstrap` under the hood (`init` is an alias for `bootstrap`). Both produce identical projects — pick whichever feels natural. See [Releases](/releases) for why both exist.
    </Callout>

  </Step>

  <Step title="Skip the prompts (optional)">
    Every prompt has a flag, so the whole thing can run non-interactively — handy in CI or when you already know what you want:

    <CodeBlock filename="terminal" language="bash" prompt>{`npx astro-ignite bootstrap my-docs --yes --template=docs --pm=pnpm`}</CodeBlock>

    | Flag | What it does |
    | --- | --- |
    | `-y`, `--yes` | Skip every prompt (and the **Proceed?** confirm) and use defaults: `starter` template, `https://example.com`, locale `en`, Resend email |
    | `--template=<starter\|docs>` | Pick the template without being asked |
    | `--pm=<pnpm\|npm\|yarn\|bun>` | Force a package manager instead of detecting one |
    | `--no-install` | Scaffold only; run the install yourself afterwards |
    | `--no-git` | Skip `git init` |

    `npx astro-ignite bootstrap --help` prints the same list.

  </Step>

  <Step title="Run it">
    <CodeBlock filename="terminal" language="bash">
      {`cd my-site
pnpm install
pnpm dev`}
    </CodeBlock>

    Open the URL printed in your terminal. With the `starter` template you should see a working site with a styled hero, a blog with example posts, a projects showcase, an about page, a working contact form (logs to console in dev), legal pages, a cookie banner, and a dark-mode toggle. The `docs` template gives you a sidebar-driven documentation site instead — it ships no contact form.

    <Callout variant="tip" title="Preview before you scaffold">
      Both templates are deployed live from `main`:
      [`starter.astroignite.dev`](https://starter.astroignite.dev) and
      [`docs-starter.astroignite.dev`](https://docs-starter.astroignite.dev). See
      [Templates](/templates) for which one to pick.
    </Callout>

  </Step>

  <Step title="Make it yours">
    Edit these first; grow into the rest over time:

    1. **Brand colors + tokens** in `src/styles/global.css` (`@theme` block)
    2. **Site identity** in `src/config/site.ts` — name, URL, organization, social
    3. **OG image** at `public/og/og-default.png` (placeholder ships)
    4. **Legal pages** in `src/content/legal/{locale}/*.mdx` — placeholders need filling, then **review with counsel before publishing**
    5. **Author bio** in `src/content/authors/jordi.json` (starter only)

  </Step>
</Steps>

<Callout variant="tip" title="No account signups required">
  In dev, missing env vars fall back to console logs — `pnpm dev` produces a
  complete working flow without any account signup. Set `RESEND_API_KEY`
  (starter contact form) and `PUBLIC_PLAUSIBLE_DOMAIN` only when you go to
  production.
</Callout>
