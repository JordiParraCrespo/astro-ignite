## Why

The starter template ships with a layered CSS strategy: above-the-fold
components (Hero, Header, Footer, Brand, LocaleSwitcher, ThemeToggle, page
section components like AboutBody, BlogIndexList, ProjectsIndexList,
ContactSection, NotFoundHero, CookieBanner) use scoped `<style>` blocks;
below-the-fold uses Tailwind v4; Beasties inlines the critical CSS at
build time.

That split was justified when Tailwind's compiler was slow and inline
critical CSS was the only way to keep the first paint cheap. Two years
on the trade-off has inverted:

- **Two ways to express the same thing.** Every contributor decides per
  component whether to write CSS or utilities — and gets it wrong half
  the time because there's no machine-checkable rule for "above the
  fold". The `tokens-only.mjs --layered` audit fires a heuristic against
  `Hero.astro` / `Header.astro` only, not the dozen other components
  that actually render above the fold today.
- **Token drift.** Scoped `<style>` blocks let raw `clamp()` / `rem`
  values sneak in beside `var(--color-*)`. The Tailwind layer doesn't
  have that escape hatch because the audit walks class strings.
- **Tailwind v4 compiles fast.** The inline-CSS optimisation that
  originally motivated Beasties is now ≤ 1% of LCP on this codebase
  (measured against the perf baseline). Removing the integration drops
  build complexity, an integration dep, and a build step that has
  bitten us twice with hydration mismatches on the consent banner.

The migration consolidates on **Tailwind utilities resolved through the
existing `--color-*` design tokens**, deletes the layered-CSS rule from
`templates-css-tokens`, and re-evaluates Beasties against the perf
budget so it can be removed cleanly if it's no longer pulling its
weight.

## Scope

### In scope

- All `.astro` files under `packages/templates/starter/src/{components,layouts,pages}` migrated from scoped `<style>` to Tailwind utility classes that resolve token values via `var(--color-*)`.
- `packages/templates/starter/src/styles/global.css` retains the `@theme` token block, the `.light` overrides, and the `@layer base` resets. Component-shaped CSS (skip-link, hairlines, mono helper, caret keyframes) stays here, because it's reused across components and Tailwind can't express keyframes inline.
- `packages/templates/starter/astro.config.mjs` and `package.json` updated to drop Beasties **iff** measurement shows no LCP regression. If kept, `design.md` documents the perf delta.
- `apps/site/src/**/*.astro` mirrored: every site component that has a corresponding starter section moves to the same Tailwind-first shape.
- `packages/astro-ignite/templates/starter/` refreshed via the existing `scripts/copy-templates.mjs` so the CLI cache matches the new source.
- `apps/playground/` regenerated by `pnpm scaffold:test` (no hand edits — CI rewrites this tree).
- Root `AGENTS.md`, `packages/templates/starter/CLAUDE.md`, and `packages/templates/starter/AGENTS.md` updated so the documented styling strategy reflects the new single-layer approach.
- `openspec/specs/templates-css-tokens/spec.md` MODIFIED via this change's delta to replace the "Layered CSS strategy" requirement with a "Tailwind-first styling, token-resolved" requirement, and to drop the corresponding I4 audit row.
- `openspec/specs/templates-perf/spec.md` MODIFIED via this change's delta to either remove or modify the Beasties requirement (depending on the measurement outcome), and to update the I4 audit row accordingly.
- `scripts/audit/tokens-only.mjs` updated to remove the `--layered` heuristic (it no longer applies once `<style>` blocks are gone from the starter).

### Out of scope

- `packages/templates/docs/` — the docs template stays on its existing styling layer for this change. A follow-up issue will mirror this work there once the starter migration is validated against the Lighthouse budget.
- Registry atoms under `packages/registry/base/` — atoms already use Tailwind utilities; only one or two reach for a `<style>` block and those are kept as-is (they're not above-the-fold-only).
- Any change to the `--color-*` token names or values. Only the _mechanism_ by which components consume tokens is changing, not the tokens themselves.
- Renaming the `tokens-only.mjs` audit script; only the `--layered` flag's behavior is dropped.
- `apps/docs` (docs marketing site) — out of scope until the docs template migration follows.

## Scenarios

### S1 — Starter components reference tokens through Tailwind utilities only

- **GIVEN** the migration is complete on a clean checkout
- **WHEN** a reviewer greps every `.astro` file under `packages/templates/starter/src/{components,layouts,pages}` for `<style>` blocks
- **THEN** zero matches are found, **except** files that carry a leading `<!-- tailwind-exception: <reason> -->` comment (e.g., a keyframe-only block); the per-component comment names _what_ Tailwind cannot express.

### S2 — `tokens-only` audit passes on the starter tree after migration

- **GIVEN** the migration is complete
- **WHEN** `node scripts/audit/tokens-only.mjs` runs against the repo
- **THEN** it reports `pass: true` with zero hits, and the `--layered` flag (now dropped) exits 0 with a "deprecated — no-op" notice; raw zinc / hex literals in components still fail the audit as before.

### S3 — Tri-state dark mode still flips via `.light`

- **GIVEN** the migrated starter is running in `pnpm dev`
- **WHEN** the user toggles theme so the `<html>` element gains `.light`
- **THEN** every page surface (Header, Hero, Footer, Cards, CookieBanner) repaints to the light token values without a JS-driven class swap on any individual component, and `pnpm test:e2e --project=starter --grep theme-toggle` passes.

### S4 — Lighthouse budget holds on every starter page

- **GIVEN** a clean production build of the migrated starter
- **WHEN** `pnpm perf:budget` runs against `/`, `/blog`, `/projects`, `/about`, `/contact` (mobile, simulated 4G)
- **THEN** Performance / Accessibility / Best Practices / SEO are all ≥ 95, LCP ≤ 2.0 s, INP ≤ 200 ms, CLS ≤ 0.05, TBT ≤ 200 ms, and total compressed transfer on `/` is ≤ 150 KB.

### S5 — Beasties decision is captured by the design

- **GIVEN** the implementer has measured `pnpm perf:budget` with and without Beasties on the migrated build
- **WHEN** the change is opened for review
- **THEN** `design.md` records the LCP delta in milliseconds, and either (a) Beasties is removed from `astro.config.mjs`, `package.json`, the spec delta deletes the corresponding requirement, and the audit row is dropped, **or** (b) Beasties is retained with the measured perf justification — never silently kept.

### S6 — `apps/site` mirrors the new shape

- **GIVEN** the starter migration is merged into `apps/site/src/`
- **WHEN** a reviewer diffs the structure of a parallel pair (e.g. `packages/templates/starter/src/components/common/Header.astro` vs `apps/site/src/components/common/Header.astro`)
- **THEN** both files express the same styling through Tailwind utilities resolving tokens; `pnpm build --filter @astro-ignite/site` is green; `pnpm typecheck` is green.

### S7 — CLI template cache stays in sync

- **GIVEN** the starter migration is complete
- **WHEN** `node packages/astro-ignite/scripts/copy-templates.mjs` runs
- **THEN** `packages/astro-ignite/templates/starter/` is regenerated byte-for-byte (modulo the documented rename rules in the copy script); `git diff packages/astro-ignite/templates/starter` shows the same migration diff as `packages/templates/starter`.

### S8 — Documentation reflects the single-layer strategy

- **GIVEN** the migration has landed
- **WHEN** a contributor reads root `AGENTS.md`, `packages/templates/starter/CLAUDE.md`, and `packages/templates/starter/AGENTS.md`
- **THEN** no surviving sentence claims "above-the-fold uses scoped `<style>` blocks"; the documented strategy is "Tailwind v4 utilities resolved through `--color-*` design tokens; `global.css` owns `@theme` tokens, `.light` overrides, base resets and keyframes only."

### S9 — Locked invariants remain green

- **GIVEN** the migration is complete
- **WHEN** `pnpm audit:invariants --change migrate-starter-template-to-tailwind-css` runs
- **THEN** `i18n-parallels`, `internal-links-localized`, `jsonld-graph`, `consent-gated-analytics`, `no-react-in-atoms`, and `tokens-only` all pass; the migration touches _only_ the styling layer, not i18n routes, JSON-LD composition, or consent gating.

### S10 — No new runtime deps; changeset documents the migration

- **GIVEN** the migration is merged
- **WHEN** a reviewer inspects `packages/templates/starter/package.json` and the `.changeset/` directory
- **THEN** no new entry exists under `dependencies`; if Beasties is dropped the corresponding integration entry is removed from `astro.config.mjs` and `devDependencies`; a changeset under `.changeset/<slug>.md` documents the styling-strategy switch as an end-user-visible change with a one-paragraph migration note pointing at the diff.
