# Run notes — restructure-starter-template-component-o

## T12 — 404 surface merge

`packages/templates/starter/src/components/blocks/not-found-state.astro`
and `packages/templates/starter/src/components/sections/not-found/NotFoundHero.astro`
were inspected. `NotFoundHero.astro` already rendered the full 404
surface (eyebrow `404`, H1, lede, CTA button back to home, with a
scoped `<style>` block for the layout container). The blocks/
not-found-state.astro file was an alternative shape with a slot-based
action list and `code` prop — it was orphaned (no page imported it).
No markup absorption was needed. The merge was therefore a deletion of
the unused `blocks/` file; the canonical 404 surface lives at
`packages/templates/starter/src/components/not-found/NotFoundHero.astro`.

## T20 — apps/playground hand-mirror not committed

The design.md calls for mirroring the chrome restructure into
`apps/playground/src/` and committing it so a fresh `git pull` reflects
the desired state. `scripts/committer` rejects every path under
`apps/playground/*` as `forbidden path` — the playground is treated by
the harness as a scaffold-only fixture, regenerated by
`pnpm scaffold:test` (T33). The hand-mirror work was prepared in
worktree (chrome moves, layout import rewrites, page rewrites,
blocks/ deletion, FeaturesGrid copied across) and verified to typecheck
clean, then reverted to keep the change set inside the committer's
allow-list. T33 (when run by the reviewer or CI) regenerates
`apps/playground/` from the now-canonical starter and produces the
final desired layout.

## Audit failures are pre-existing on `main`

The audit dispatch (`pnpm audit:invariants --change ...`) surfaces
five `❌ FAIL` rows. Each was reproduced on `main` (pre-change) and is
unrelated to this restructure:

- `internal-links-localized` — `SidebarNav.astro:64 — <Brand href="/" ...>`
  is the same hardcoded link the audit has always flagged in the docs
  template.
- `tokens-only` (×2) — `themeColor: '#fafafa'` / `'#0a0a0a'` in
  `config/site.ts` for both templates are the same hex literals the
  audit has always flagged.
- `consent-gated-analytics` — `ArticleLayout.astro: base layout does
  not render CookieBanner` — the audit's `find(/Base|Layout|RootLayout/)`
  picks `ArticleLayout` (which inherits from `BaseLayout`); the same
  hit appears on `main`.
- `consent-gated-analytics` (×2) — `CookieBanner present but no
  /legal/cookies(.astro|.mdx) page` — the templates serve the cookie
  policy via `pages/legal/[...slug].astro` (content collection), not a
  static `cookies.astro` page; the audit doesn't understand the
  dynamic route and emits the same hit on `main`.

No new audit failure is introduced by this change. JSON-LD,
i18n-parallels, consent boundary (--boundary), and registry blocks
audits all pass.
