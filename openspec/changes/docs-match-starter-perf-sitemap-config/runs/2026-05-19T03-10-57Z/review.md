## Changes requested

1. **`pnpm audit:invariants` is red because of pre-existing
   `tokens-only` hex literals.** Two violations:
   - `packages/templates/docs/src/config/site.ts:68` —
     `themeColor: '#fafafa',`
   - `packages/templates/starter/src/config/site.ts:107` —
     `themeColor: '#0a0a0a',`

   Both reproduce on `main` and are not touched by this change. The
   prior `starter-use-the-text-component-for-all-t` review documented
   the same blocker and offered two fixes; either is acceptable here
   (each in a **separate** change so the parity diff stays
   reviewable):
   - **(a)** Refactor the `themeColor` field on `siteConfig` to a
     token reference (`'var(--color-bg)'` or the resolved
     theme-color token), and update the consumer in `Layout.astro` to
     emit the meta tag from the token. Add
     `packages/templates/*/src/config/site.ts` to the next change's
     `design.md` "Files touched", OR
   - **(b)** Narrow `scripts/audit/tokens-only.mjs` to exempt the
     `themeColor:` line in `config/site.ts` (the `<meta
name="theme-color">` value is required by the browser to be a
     concrete colour, not a token reference; the audit should
     acknowledge that exemption).

2. **`pnpm perf:budget` is red because the Lighthouse binary is not
   installed in the reviewer environment.** Three FAIL rows for
   `--page /`, `--page /quick-start`, and `--transfer` ("not yet
   wired"). The change touches `templates-*` capabilities, so the
   harness rule `require_perf_budget_to_close_when` makes the perf
   gate mandatory. Two options:
   - **(a)** Re-run this exact change's reviewer on an environment
     with Chrome for Testing installed (`pnpm dlx lighthouse` or the
     `scripts/doctor/chrome-installed.mjs` install path). Confirm
     Performance / Accessibility / Best Practices / SEO ≥ 95 on `/`
     and `/quick-start` for both the docs template and `apps/docs`,
     LCP ≤ 2.0 s, total compressed transfer on `/` ≤ 150 KB, and
     FCP / Speed Index do not regress vs. the previous recorded
     baseline. The implementer's `perf.txt` documents the expected
     directional impact; the live numbers replace the deferral row.
   - **(b)** As a separate harness change, install Chrome for Testing
     in the headless reviewer container (or wire `scripts/perf/run.mjs
--transfer` to a brotli-only static check that doesn't need a
     browser binary, for the cases where Lighthouse is genuinely
     unavailable). This is the more durable fix — it unblocks every
     future `templates-*` change.

3. **`pnpm format:check` flags the regenerated `audit.md` /
   `perf.md`.** Not a source-tree issue and not on the critical path
   for this verdict, but documenting it so the next pass can either
   (a) make `scripts/audit/run-all.mjs` emit prettier-clean tables
   (blank lines around headings, padded table columns), or (b) add
   `openspec/changes/**/runs/**/*.md` to `.prettierignore`. Pick one;
   the present state leaves a permanent format-check redness on every
   reviewer re-run.
