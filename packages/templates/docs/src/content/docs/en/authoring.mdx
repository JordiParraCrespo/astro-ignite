Every component below is registered in `src/components/docs/mdx-components.ts`,
the component map handed to every rendered doc. Inside the `docs` collection you
use them directly — no `import` line needed. They are plain Astro + vanilla JS,
token-resolved, and yours to edit.

<Callout variant="info" title="When you do need an import">
  Only atoms that are *not* in the map need one. The `Card` family is the usual
  case — this page imports `Card`, `CardHeader`, `CardTitle`, and `CardDescription`
  from `@/components/ui/card/` at the top. Outside the docs collection (a plain
  `.astro` page, a blog post), import every component you use.
</Callout>

## Hero

`<Hero>` is the opening block of a landing page. It owns the page's `<h1>`, so
pair it with `landing: true` in the frontmatter — the layout then skips its
standard header, drops the on-this-page column, and lets the content run full
width. The default slot is the lede; the `actions` slot is a row of buttons.

```mdx
---
title: Introduction
description: What this project is and what it gives you out of the box.
landing: true
---

<Hero title="Ship a docs site in five prompts." eyebrow="astro-ignite">
  One paragraph on what this is.
  <Fragment slot="actions">
    <Button href="/quick-start" size="lg">Quick start</Button>
    <Button href="https://github.com/…" variant="outline" size="lg">GitHub</Button>
  </Fragment>
</Hero>
```

Props: `title` (required), `eyebrow` (small label above the title), `class`.
The introduction page of this site is built exactly this way.

## Buttons

The `Button` atom is registered for MDX, so you can use it in a hero's
`actions` slot or anywhere inline. With `href` it renders an anchor; without it,
a `<button>`. Variants: `default` · `secondary` · `outline` · `ghost` ·
`destructive` · `link`. Sizes: `sm` · `md` · `lg` · `icon`.

<div class="flex flex-wrap gap-2">
  <Button href="/quick-start">Default</Button>
  <Button href="/quick-start" variant="secondary">Secondary</Button>
  <Button href="/quick-start" variant="outline">Outline</Button>
  <Button href="/quick-start" variant="ghost">Ghost</Button>
  <Button href="/quick-start" variant="link">Link</Button>
</div>

```mdx
<Button href="/quick-start" size="lg">Quick start</Button>
<Button href="/quick-start" variant="outline">Secondary action</Button>
```

## Callouts

`<Callout>` highlights important content. The layout follows the shadcn alert:
a two-column grid with a fixed icon column, the title tinted to the variant's
status color, and the body in muted foreground. Tint and border derive from the
status tokens, so the block adapts to light and dark themes without extra tokens.

<Callout variant="note" title="Note (default)">
  An informational aside or context the reader should know.
</Callout>

<Callout variant="info" title="Info">
  Background context worth knowing before you start.
</Callout>

<Callout variant="tip" title="Tip">
  A suggestion that makes something faster or easier.
</Callout>

<Callout variant="check" title="Check">
  Confirms a step worked — what success looks like.
</Callout>

<Callout variant="warning" title="Heads up">
  Something the reader should check before proceeding.
</Callout>

<Callout variant="danger" title="Warning">
  An action that could cause data loss or breakage.
</Callout>

```mdx
<Callout variant="tip" title="Custom title">
  Body copy goes in the default slot — any MDX is fine.
</Callout>
```

`variant` accepts `note` · `info` · `tip` · `check` · `warning` · `danger` (default: `note`).
`title` is optional — each variant has a built-in default.

## Steps

Use `<Steps>` with nested `<Step title="…">` for ordered walkthroughs. The
number badge and the connecting rail are CSS counters drawn by `Step.astro`
through Tailwind `before:` / `after:` utilities — no client JS, and reordering
renumbers automatically.

<Steps>
  <Step title="Open the wrapper">Start a `<Steps>` block anywhere in your MDX.</Step>
  <Step title="Add the items">Each `<Step>` becomes a numbered item; the rail joins them.</Step>
  <Step title="Ship">No client JS, no configuration.</Step>
</Steps>

```mdx
<Steps>
  <Step title="Open the wrapper">…</Step>
  <Step title="Add the items">…</Step>
</Steps>
```

## Card groups

`<CardGroup cols={2|3|4}>` lays cards out in a responsive grid that collapses to
one column on mobile. Pair it with the `Card` atom (imported — see the note at the top).

<CardGroup cols={2}>
  <Card>
    <CardHeader>
      <CardTitle>Tokens</CardTitle>
      <CardDescription>Edit `global.css` to reskin the whole site.</CardDescription>
    </CardHeader>
  </Card>
  <Card>
    <CardHeader>
      <CardTitle>i18n</CardTitle>
      <CardDescription>Parallel routes per locale, ready when you are.</CardDescription>
    </CardHeader>
  </Card>
</CardGroup>

## Tabbed code

`<CodeGroup>` combines several `<CodeBlock>` children into one tabbed panel.
Each child's `filename` becomes a tab — the npm/pnpm/yarn pattern, or
curl/python/node for an API. The active tab persists in `localStorage` and syncs
every group on the page, so picking `pnpm` once holds across snippets and visits.

<CodeGroup>
  <CodeBlock filename="npm" prompt>{`npm create astro-ignite@latest my-docs`}</CodeBlock>
  <CodeBlock filename="pnpm" prompt>{`pnpm create astro-ignite my-docs`}</CodeBlock>
  <CodeBlock filename="yarn" prompt>{`yarn create astro-ignite my-docs`}</CodeBlock>
</CodeGroup>

`<CodeBlock>` on its own takes `filename`, `language`, and `prompt`. `prompt`
renders a muted `$ ` shell prefix as a pseudo-element, so it is never part of the
copied text.

## Fenced code

Plain fenced blocks are highlighted at build time by Shiki with a light/dark
theme pair — `github-light` and `github-dark` — and the page picks the one
matching the site theme, so code follows the toggle with no flash. Every fenced
block gets a copy button that appears on hover (or focus), and multi-line blocks
get a line-number gutter.

Two Shiki transformers add line highlighting and diff markers — zero client
cost. Add `{1,3-5}` after the language, or annotate lines inline with
`// [!code highlight]`, `// [!code ++]`, and `// [!code --]`.

```js {2}
const config = {
  primary: 'var(--color-primary)', // highlighted
  border: 'var(--color-border)',
};
```

```js
const before = 1; // [!code --]
const after = 2; // [!code ++]
```

## Frames

`<Frame caption="…">` centers and frames media so screenshots and diagrams look
intentional. Drop an `Image` atom or a plain `<img>` inside.

<Frame caption="A framed, captioned figure">
  <img src="/og/og-default.png" alt="Open Graph preview card" width="600" height="315" />
</Frame>

## Tabs

The `Tabs` atom family is registered for MDX, so switchers work without
imports. Arrow keys move between triggers.

<Tabs defaultValue="npm">
  <TabsList>
    <TabsTrigger value="npm">npm</TabsTrigger>
    <TabsTrigger value="pnpm">pnpm</TabsTrigger>
    <TabsTrigger value="yarn">yarn</TabsTrigger>
  </TabsList>
  <TabsContent value="npm">Run `npm create astro-ignite my-site`.</TabsContent>
  <TabsContent value="pnpm">Run `pnpm create astro-ignite my-site`.</TabsContent>
  <TabsContent value="yarn">Run `yarn create astro-ignite my-site`.</TabsContent>
</Tabs>

## Accordion

`<Accordion>` + `<AccordionItem>` — native `<details name>`, so single-open
grouping needs no JS state.

<Accordion>
  <AccordionItem title="Does this template use Starlight?">
    No — the docs primitives are composed from the astro-ignite base components and owned by
    this repo.
  </AccordionItem>
  <AccordionItem title="Can I add a second locale?">
    Yes. Add it to `siteConfig.locales` and the parallel routes activate.
  </AccordionItem>
</Accordion>

## Expandable

`<Expandable>` is an inline disclosure for nested object shapes — distinct from
Accordion. Nest `<ParamField>` rows inside to document properties. Props:
`title` (required), `hint`, `open`.

## Fields

`<ParamField>` documents request parameters; `<ResponseField>` documents
response fields. Both take `type`, `required`, `default`, and `deprecated`;
`ParamField` adds a `location` pill (`body`, `query`, `path`, `header`). The
rows below document a made-up deploy endpoint to show the anatomy.

#### Request parameters

<ParamField name="site" type="string" location="body" required>
  Target site slug. Lowercase, dashes only — matches the directory name.
</ParamField>
<ParamField name="locales" type="string[]" location="body" default="['en']">
  Locale scopes to generate. Each adds a routed subtree and sitemap block.
</ParamField>
<ParamField name="email" type="object" location="body">
  Transactional email config. Expand to see `provider` and `from`.
</ParamField>
<ParamField name="legacySlug" type="string" location="body" deprecated>
  Kept for older clients. Use the `redirects` map instead.
</ParamField>

#### Response fields

<ResponseField name="id" type="string">Unique deploy id, format `dep_xxxxxxxx`.</ResponseField>
<ResponseField name="status" type="'queued' | 'building' | 'ready'">
  Current lifecycle stage. Poll until `ready`.
</ResponseField>

## Icon

`<Icon name="…" size={…} />` renders an inline lucide-style stroke icon in
`currentColor`. Run <Icon name="terminal" size={15} /> `pnpm dev` to start,
then deploy with <Icon name="rocket" size={15} /> one command. Props: `name`
(required), `size` (px, default 16), `stroke` (default 1.6).

Sizes: <Icon name="zap" size={14} /> <Icon name="zap" size={18} /> <Icon name="zap" size={24} /> <Icon name="zap" size={32} />

```mdx
Run <Icon name="terminal" size={15} /> `pnpm dev` to start.
```

## Tree

`<Tree items={…}>` renders a file/folder tree. Connectors are box-drawing
glyphs — copy/paste safe, no images. Icons derive from the structure
(`folder` when an item has children, `file-code` for code extensions) and can
be overridden per item with `icon`; `tag` adds a label and `muted` dims a row.

<Tree
  items={[
    {
      name: 'my-site/',
      children: [
        {
          name: 'src/',
          children: [
            {
              name: 'pages/',
              children: [{ name: 'index.astro' }, { name: 'blog/[slug].astro' }],
            },
            { name: 'content/', children: [{ name: 'config.ts', icon: 'file' }] },
            { name: 'lib/', icon: 'folder', muted: true, tag: 'empty' },
          ],
        },
        { name: 'astro.config.mjs' },
        { name: 'plan.md', tag: 'generated' },
        { name: 'package.json' },
      ],
    },
  ]}
/>

## Update

`<Update>` renders dated changelog entries on a timeline. The rail connecting
consecutive entries draws itself — no `last` prop. Tags `minor`, `patch`, and
`breaking`/`major` are color-coded. The entries below are sample content for a
fictional project, not a real changelog.

<Update date="Sep 12" version="1.2.0" tag="minor" title="Search across locales">
  The search index now covers every locale, and results open in the language you are
  reading.
</Update>
<Update date="Aug 30" version="1.1.3" tag="patch" title="Sidebar overflow">
  Long group labels wrap instead of clipping on narrow viewports.
</Update>
<Update date="Aug 02" version="1.0.0" tag="breaking" title="Node 22 minimum">
  Node 20 is no longer supported. Update your CI image before upgrading.
</Update>

## Mermaid

`<Mermaid code={…}>` renders a diagram from mermaid source, themed by the
design tokens. The library loads lazily — only when a diagram scrolls into
view — so pages without diagrams ship zero extra JS. Diagrams re-render when
the theme toggles.

<Mermaid
  code={`graph TD
  A[src/] --> B[parse MDX]
  B --> C{budget ok?}
  C -->|yes| D[emit static]
  C -->|no| E[fail CI]`}
/>

## Columns

`<Columns cols={2|3|4}>` is the generic grid wrapper — unlike `CardGroup` it
takes any content. Columns collapse to one per row below the `md` breakpoint.

<Columns cols={3}>
  <Card>
    <CardHeader>
      <CardTitle>Fast by default</CardTitle>
      <CardDescription>Inlined CSS, no framework runtime, Lighthouse gated in CI.</CardDescription>
    </CardHeader>
  </Card>
  <Card>
    <CardHeader>
      <CardTitle>i18n built in</CardTitle>
      <CardDescription>Locale-scoped routes, sitemaps, and hreflang tags.</CardDescription>
    </CardHeader>
  </Card>
  <Card>
    <CardHeader>
      <CardTitle>Typed frontmatter</CardTitle>
      <CardDescription>Zod-validated at build — a bad field fails the build.</CardDescription>
    </CardHeader>
  </Card>
</Columns>

## Banner

`<Banner>` is a site-wide announcement strip. Drop the `solid` variant into a
layout above the header, or use `subtle` inline. Dismissal persists per `id` in
localStorage — bump the id to resurface a new announcement. Props: `id`
(required), `variant`, `icon`, `href`, `linkText`, `dismissible`.

<div class="overflow-hidden rounded-md border border-border">
  <Banner id="demo-solid" href="#banner" linkText="Read more">
    A demo banner — dismiss it and reload; it stays hidden until the id changes.
  </Banner>
</div>

<Banner id="demo-subtle" variant="subtle">
  Scheduled maintenance Sat 02:00–03:00 UTC. Builds may queue.
</Banner>

## Tiles

`<Tiles>` + `<Tile>` build a compact navigation grid — lighter than cards. Each
tile lifts on hover, the border darkens, and the arrow nudges right. `Tile`
takes `title`, `href`, and an optional `icon`.

<Tiles cols={3}>
  <Tile icon="rocket" title="Quick start" href="/quick-start">
    Scaffold, run, and deploy a site in under five minutes.
  </Tile>
  <Tile icon="book" title="Writing content" href="/authoring">
    Every MDX component you can drop into a page.
  </Tile>
  <Tile icon="git-branch" title="Roadmap" href="/roadmap">
    What is stable, what is next, and what is out of scope.
  </Tile>
</Tiles>
