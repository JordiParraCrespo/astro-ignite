# Internationalisation (i18n)

The docs template uses Astro's native i18n with **parallel routes**. Each docs page lives in a locale-prefixed subfolder of the content collection. The sidebar resolves slugs per locale at render time. This guide explains how the system works and how to extend it.

## Configuration

All locale settings live in `src/config/site.ts`:

```ts
export const siteConfig = {
  locales: ['en'],          // add more here: ['en', 'es', 'fr']
  defaultLocale: 'en',
  name: { en: 'My Docs', es: 'Mis Docs' },
  description: { en: '...', es: '...' },
  organization: {
    en: { name: 'Acme Inc.', legalName: 'Acme Inc.' },
    es: { name: 'Acme S.L.',  legalName: 'Acme S.L.' },
  },
};
```

With only one locale, the `[lang]/` parallel routes are dormant — no `/es/introduction` etc. are emitted.

## Route pattern

```
src/pages/
├── index.astro              # /           (default locale docs index)
├── [...slug].astro          # /<slug>     (default locale docs pages)
├── legal/[...slug].astro    # /legal/<page>
└── [lang]/
    ├── index.astro          # /es/
    ├── [...slug].astro      # /es/<slug>
    └── legal/[...slug].astro
```

The `[lang]` directory name is canonical — do not rename it. The param is read as `Astro.params.lang`.

`getStaticPaths` in each `[lang]/*` route emits one entry per non-default locale, per doc:

```ts
export async function getStaticPaths() {
  const entries = await getCollection('docs');
  const langs = siteConfig.locales.filter(l => l !== siteConfig.defaultLocale);
  return langs.flatMap(lang =>
    entries
      .filter(e => e.id.startsWith(`${lang}/`) && !e.data.draft)
      .map(e => ({ params: { lang, slug: e.id.replace(`${lang}/`, '') } }))
  );
}
```

## Content collection layout

Docs entries live at `src/content/docs/{locale}/{slug}.mdx`. The content collection id is `{locale}/{slug}` (e.g. `en/introduction`). The sidebar config references slugs **without** the locale prefix — the resolver adds the current locale at render time:

```
src/content/docs/
├── en/
│   ├── introduction.mdx         # → /introduction
│   └── guide/
│       └── install.mdx          # → /guide/install
└── es/
    ├── introduction.mdx         # → /es/introduction
    └── guide/
        └── install.mdx          # → /es/guide/install
```

Sidebar grouping is **not** derived from this folder structure — it's manual. Edit the `SidebarGroup[]` array in `src/config/sidebar.ts` to add or rename groups and list each item's slug.

## Sidebar and locale

The sidebar in `src/config/sidebar.ts` uses locale-neutral slugs. The `SidebarNav` component prepends `/${lang}/` to doc slugs for non-default locales automatically. Absolute-path slugs (starting with `/`) are used as-is without locale prefix.

When a page exists in one locale but not another (e.g. `en/advanced.mdx` exists, `es/advanced.mdx` doesn't), `SidebarNav` automatically hides that item for locales where a localized entry isn't found — it never renders a link that would 404. Add the translated file to make the item reappear.

## Internal links

Always use `getRelativeLocaleUrl` — never hardcode paths:

```astro
---
import { getRelativeLocaleUrl } from 'astro:i18n';
const { lang } = Astro.params;
---

<a href={getRelativeLocaleUrl(lang ?? siteConfig.defaultLocale, '/introduction')}>
  Introduction
</a>
```

On default-locale pages, `lang` is `undefined` — fall back to `siteConfig.defaultLocale`.

## UI strings

Per-locale labels for nav items, button text, etc. live in `src/i18n/<locale>.json`. Load them via `useTranslations`:

```ts
import { useTranslations } from '@/i18n';
const t = useTranslations(lang ?? siteConfig.defaultLocale);
t('sidebar.startHere') // → "Start here" or translated equivalent
```

To add a new i18n key: add it to `en.json`, then add translated values to every other locale file.

## Adding a locale

1. **`src/config/site.ts`** — add the locale code and translate metadata:
   ```ts
   locales: ['en', 'es'],
   name: { en: 'My Docs', es: 'Mis Docs' },
   ```

2. **`src/i18n/es.json`** — copy `en.json`, translate every value.

3. **Content** — copy `src/content/docs/en/*.mdx` to `src/content/docs/es/` and translate body + frontmatter.

4. **Legal pages** — copy `src/content/legal/en/*.mdx` to `src/content/legal/es/` and translate.

5. **OG image** (optional) — add `public/og/og-es.png`, update `siteConfig.defaultOgImage`.

6. **Verify** — `pnpm build`. Missing locale entries in `getStaticPaths` surface as build errors.

## LocaleSwitcher

The `<LocaleSwitcher>` in the header links to the equivalent page in each locale. If the current page doesn't exist in a given locale, the switcher still links there — landing on a 404 is the signal to add the translated page. There is no automatic fallback to the default-locale content.

## RSS feed

The docs template ships an RSS feed at `/rss.xml` (default locale) and `/{lang}/rss.xml` (other locales), but it indexes docs pages rather than blog posts. If you don't want an RSS feed for docs, remove `src/pages/rss.xml.ts` and `src/pages/[lang]/rss.xml.ts`.

## Common mistakes

- **Locale prefix in sidebar slugs** — sidebar items should be `'introduction'`, not `'en/introduction'`. The renderer adds the prefix.
- **Hardcoded paths** (`href="/guide/install"`) — breaks non-default locales. Always use `getRelativeLocaleUrl`.
- **Missing `[lang]` parallel route** — adding a top-level page without a `[lang]` mirror makes it untranslatable.
- **Mismatched folder nesting** — `en/guide/install.mdx` and `es/guia/instalacion.mdx` produces different URL structures across locales. Keep folder structure identical.
