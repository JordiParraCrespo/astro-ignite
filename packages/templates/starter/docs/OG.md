# OG images

Open Graph images are the social-share moment of truth — they show up in every link unfurl on Twitter/X, LinkedIn, Slack, iMessage, Discord. The template ships with a pre-baked default + per-content override, plus a documented upgrade path to dynamic generation.

## Default behavior

The overall OG image resolves in this order:

1. `entry.data.ogImage` — `ArticleLayout`/`ProjectLayout` pass the collection entry's `ogImage` down as the `image` prop
2. The `image` prop passed directly to `<BaseLayout>`/`<SEO>` (per-page override, for pages with no collection entry)
3. `siteConfig.defaultOgImage[locale]` if locale-keyed
4. `siteConfig.defaultOgImage` if a string

`src/components/seo/SEO.astro` itself only implements steps 2–4 — it has no knowledge of collection entries; step 1 happens one layer up, in the layout that calls it.

The default file is `public/og/og-default.png` (1200×630) — a placeholder gradient with the site name baked in.

## Brand the default OG

Replace `public/og/og-default.png` with your own 1200×630 PNG. That's it.

The placeholder was generated by a monorepo-only script (`scripts/generate-placeholder-assets.mjs` in the astro-ignite source repo) — it does not ship as part of this scaffolded project, so it isn't available to run here. Replacing the PNG directly (above) is the supported path for a scaffolded project.

## Per-locale OG images

Edit `src/config/site.ts`:

```ts
defaultOgImage: {
  en: '/og/og-en.png',
  es: '/og/og-es.png',
  fr: '/og/og-fr.png',
},
```

Drop the corresponding files into `public/og/`. The `<SEO>` component picks the right one based on `Astro.currentLocale`.

## Per-content OG images

Each blog post and project entry has an optional `ogImage` field in frontmatter:

```mdx
---
title: My post
description: …
ogImage: ./og.png # 1200×630, optional — overrides the site-wide default for this post
---
```

> **Note:** There is no `heroImage` field — post cards and detail pages render a token-resolved CSS gradient cover, not a hero image. `ogImage` is the only image field in the schema; it controls the social-share preview only.

For projects (folder-per-slug structure), colocate `og.png` next to `index.mdx`. For blog (flat file structure), put it in `_assets/` and reference relatively.

## Add dynamic OG generation

This template's own banner pipeline (used for astro-ignite's blog hero images) generates OG PNGs from an HTML source rendered through headless Chrome — **not** through text-composition libraries. Follow the same approach for per-post OG images:

1. Author an HTML source per post (or a single templated HTML source parameterized by title/subtitle) that follows your design tokens — plain HTML + CSS, no framework.
2. Render it to PNG with a headless-Chrome driver (Playwright or Puppeteer) at build time, sized 1200×630.
3. Save the output next to the post (for projects, colocate with `index.mdx`; for blog, put it in `_assets/`) and reference it from the post's `ogImage` frontmatter field.

**Do not** reach for `satori` / `@vercel/og` / `resvg` for this — type rendering from those libraries drifts from the design tokens (see the root `AGENTS.md`'s "Banner & hero images" section, which forbids this class of tool for OG/banner generation project-wide).

## OG image dimensions

- **Recommended:** 1200×630 (1.91:1 ratio)
- **Twitter `summary_large_image`:** same — works for both
- **LinkedIn:** same — works
- **Discord/Slack:** any size, but 1200×630 renders consistently

The `<SEO>` component hardcodes `og:image:width=1200` and `og:image:height=630`. If you ship a different size, update those meta tags in `src/components/seo/SEO.astro`.

## Twitter Card type

The component picks `summary_large_image` if any image is set, `summary` otherwise. The large card type is what you want for visual content sites.
